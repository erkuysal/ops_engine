# OpsEngine: Global Detect Command

## Overview

The `ops detect` command performs recursive infrastructure scanning from your project root, automatically discovering all DevOps configurations and writing them to `opsengine.conf` in **KEY=VALUE** format.

## Command Syntax

```bash
ops detect [mode]
```

### Modes

| Mode | Description | Config Written |
|------|-------------|----------------|
| `--deep` | Deep recursive scan (max depth: 5) | Yes |
| `--write` | Standard detection with config write | Yes |
| `--dry-run` | Detection only, no config changes | No |
| (default) | Standard detection with config write | Yes |

- Environment files (.env, .env.*)

## Using the Generated Config

### In Shell Scripts
```bash
#!/bin/bash
source opsengine.conf

# Use detected paths
echo "Building from: $DOCKERFILE_BACKEND_DOCKERFILE_PATH"
docker build -f "$DOCKERFILE_BACKEND_DOCKERFILE_PATH" -t myapp:latest backend/

# Access all compose files
for i in {1..3}; do
    compose_var="COMPOSE_PATH_$i"
    if [[ -n "${!compose_var}" ]]; then
        echo "Compose: ${!compose_var}"
    fi
done
```

### In Python
```python
import os

# Load config
config = {}
with open('opsengine.conf') as f:
    for line in f:
        if '=' in line and not line.startswith('#'):
            key, value = line.strip().split('=', 1)
            config[key] = value.strip('"')

# Use paths
backend_dockerfile = config['DOCKERFILE_BACKEND_DOCKERFILE_PATH']
print(f"Backend Dockerfile: {backend_dockerfile}")
```

### In Node.js
```javascript
const fs = require('fs');

// Load config
const config = {};
const content = fs.readFileSync('opsengine.conf', 'utf8');
content.split('\n').forEach(line => {
  if (line.includes('=') && !line.startsWith('#')) {
    const [key, value] = line.split('=', 2);
    config[key] = value.replace(/"/g, '');
  }
});

// Use paths
console.log('Frontend package:', config.PACKAGE_FRONTEND_WEB_PACKAGE_JSON_PATH);
```

### With OpsEngine Modules
```bash
# Detection already done, modules use the config
ops docker integrate   # Uses DOCKERFILE_* and COMPOSE_* variables
ops build integrate    # Uses PACKAGE_* and MAKEFILE_* variables
ops cicd integrate     # Uses GITHUB_WORKFLOW_* variables
```

### Integration with CI/CD

```yaml
# .github/workflows/ci.yml
name: CI with Auto-Detection

on: [push]

jobs:
  detect-and-build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Run detection
        run: |
          ./opsengine/install.sh
          ops detect --deep
      
      - name: Use detected paths
        run: |
          source opsengine.conf
          echo "Building: $DOCKERFILE_BACKEND_DOCKERFILE_PATH"
          docker build -f "$DOCKERFILE_BACKEND_DOCKERFILE_PATH" -t app:${{ github.sha }} .
```

## Key Features

### ✅ Recursive Scanning
- Searches from project root down
- Configurable depth (default: 5 levels)
- Skips node_modules, .git directories

### ✅ Comprehensive Detection
- **Docker:** All Dockerfiles + analysis
- **Compose:** All docker-compose files + services
- **CI/CD:** GitHub, GitLab, CircleCI, Jenkins
- **Build:** package.json, Makefile, scripts
- **Environment:** All .env files

### ✅ Structured Output
- Clear KEY=VALUE format
- Grouped by category
- Comments for readability
- Uppercase keys for consistency

### ✅ Safe Operations
- Automatic config backup
- Timestamped backups
- Dry-run mode available
- Non-destructive detection

### ✅ Shell Integration
- Easy to source in scripts
- Standard environment variables
- Compatible with all shells

## Troubleshooting

### Config Not Written
```bash
# Check if you have write permissions
ls -la opsengine.conf

# Use --write explicitly
ops detect --write
```

### Missing Paths
```bash
# Increase depth for deeper nesting
# Edit core/integration.sh, line: local max_depth="${2:-5}"
# Change 5 to 10 or more

# Or ensure files aren't in ignored directories
```

### Old Config
```bash
# Clear and re-detect
mv opsengine.conf opsengine.conf.old
ops detect --deep
```
